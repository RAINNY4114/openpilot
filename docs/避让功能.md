# 障碍物自动避让/高速自动超车（dp_lincoln_auto_avoid / dp_lincoln_auto_overtake）功能说明（独立文档）

> 目标：当检测到**本车道前方障碍物**（锥桶/车辆类等）时，先进行纵向减速限速，再在满足安全门控后自动发起一次绕行变道，并在障碍物清除后自动回到原车道；同时在 HUD 上绘制目标框，并提供提示音。
>
> 重要：该功能为**实验性**，依赖 BSM（盲点）传感器，只建议在安全环境中验证；驾驶员必须随时准备接管。

---

## 1. 开关与前提

### 1.1 Lincoln 面板开关（UI）

代码位置：`selfdrive/ui/layouts/settings/lincoln.py`

- `dp_lincoln_auto_avoid`（bool）
  - 含义：启用自动避让（减速 + 自动变道绕行 + 回正）
- `dp_lincoln_auto_overtake`（bool）
  - 含义：启用高速自动超车（基于 lead 慢车，自动变道超车 + 回正）
- 危险提示音（Hazard alerts）：默认开启（无独立开关）
  - 含义：检测到危险目标进入当前车道前方时播放提示音（仅提示，不改变方向/制动策略）
- 目标检测（`coned`）：上路自动运行（Ford/Lincoln），无需依赖自动避让/自动超车开关（用于 HUD 目标框与安全门控）
  - 含义：用于 HUD 目标框、危险提示音，以及相邻车道安全门控（前侧方/并行车保护）

### 1.1.1 HUD 快捷偏好车道（单按钮循环）

代码位置：
- HUD 按钮绘制/点击：`selfdrive/ui/onroad/lane_pref_button.py`
- HUD 布局挂载：`selfdrive/ui/onroad/hud_renderer.py`

显示条件：
- 仅当 `dp_lincoln_auto_avoid` 或 `dp_lincoln_auto_overtake` 开启时，HUD 才显示该按钮（避免在未启用自动变道功能时占用界面空间）。

参数键：
- `dp_lincoln_lane_preference`（int）
  - `0`：AUTO（默认，超车后按状态机条件回正）
  - `1`：KEEP LEFT（超车后保持左侧，不自动回正）
  - `2`：KEEP RIGHT（RHD 下超车后保持右侧不自动回正；LHD 下等价于 AUTO 的回正行为）

说明：该按钮只改变“超车后是否自动回正”的策略，不做“哪边堵走哪边”的全局择道。

### 1.2 硬件/运行前提（严格按代码）

- **必须有 BSM**：`carParams.enableBsm == 1`
  - 自动变道绕行会被硬门控；无 BSM 时不会绕行，并在必要时兜底停车（见 §5/§6）。
- **必须横向激活**：`carControl.latActive == True`
  - 自动变道请求仅在横向激活时产生（`selfdrive/modeld/modeld.py`）。
- **最低车速**：`vEgo >= 30 km/h`
  - `AUTO_AVOID_MIN_SPEED = 30 km/h`（`selfdrive/controls/lib/auto_avoidance.py`）。
- **驾驶员打灯时不自动避让**：若检测到单边转向灯（`leftBlinker != rightBlinker`），自动避让状态机会 reset（`auto_avoidance.py`）。
- **弯道中禁止自动变道**：当 `laneChangeState==off` 且当前曲率（由 `yawRate/vEgo` 估算）超过速度相关阈值时，自动避让/自动超车都不会发起自动变道请求（`selfdrive/modeld/modeld.py`）。

### 1.3 高速自动超车（dp_lincoln_auto_overtake）触发条件（严格按代码）

代码：
- 变道请求注入：`selfdrive/modeld/modeld.py`
- 状态机/门限：`selfdrive/controls/lib/auto_overtake.py`

硬门控（任一不满足则不触发，且状态机 reset）：
- `dp_lincoln_auto_overtake==1` 且 `carControl.latActive==True`
- `carParams.enableBsm==1`（无 BSM 不会自动变道）
- `carState.cruiseState.enabled==True`
- 车速门限：`vEgo >= 80 km/h`
- 巡航设定门限：`vCruise >= 90 km/h`

慢车触发（满足并稳定一段时间后，才会发起超车请求）：
- Lead 来源：`radarState.leadOne`（雷达/无雷达平台都会提供）
- 触发条件（见 `auto_overtake.py` 常量）：
  - `(vCruise - vLead) >= 15 km/h`
  - `dRel / vEgo <= 2.8 s`（接近到会被慢车“限速”的距离）
  - 连续满足 `>= 1.0 s`

行为（同样严格按代码）：
- 超车方向：默认按交通规则侧超车（LHD→左侧，RHD→右侧）
- 发起超车：先等待 `0.6 s`（抗抖），再请求一次变道
- 回正：当不再满足慢车触发条件并持续 `>= 5.0 s`，且变道完成后至少 `4.0 s`，则请求回到原车道
- 冷却：一次完整往返后 `20 s` 内不再发起下一次自动超车

## 3. 目标检测（coned）细节

### 3.1 模型与类别

- 模型文件：`selfdrive/modeld/models/Cone_YOLO11n.onnx`
- 构建产物：`selfdrive/modeld/models/Cone_YOLO11n_tinygrad.pkl`（由 `selfdrive/modeld/SConscript` 生成）
- 类别（COCO 索引）：
  - 模型本身包含 **COCO-80（0..79）+ traffic cone(80)** 共 81 个标签。
  - **HUD 画框/调试**：`coned` 现在会把 **0..80 全类别**都输出到 `objs/objsR`（见 §7），不再只画“人/车/锥桶”子集。
  - **自动避让/自动超车门控**：仍然只使用“驾驶相关”的少数类别来生成 `*InPath/*Metric`（行人/两轮/四轮/锥桶），保持保守与可控（见 §3.3/§3.4）。

### 3.2 推理与过滤参数（默认值）

代码：`selfdrive/modeld/coned.py`

- `CONE_SCORE_MIN = 0.10`
- `PERSON_SCORE_MIN = 0.25`
- `VEHICLE_SCORE_MIN = 0.30`
- `CONE_OTHER_SCORE_MIN = 0.25`（其余类别用于 HUD 画框的默认阈值）
- `CONE_PERSON_AREA_MIN_FRAC = 0.004`
- `CONE_VEHICLE_AREA_MIN_FRAC = 0.010`
- `CONE_TWOWHEEL_AREA_MIN_FRAC = 0.006`
- `NMS_IOU_THRES = 0.45`
- `CONE_MAX_DET = 64`（`coned` 输出到 `objs/objsR` 的 Top-N 检测数量）
- `PUB_HZ = 10`（10Hz 发布一次检测结果）
- `CONE_REFINE_MAX_OBJS = 32`（每次发布最多做多少个框的边缘收紧；其余框直接用 YOLO 原始框）

以上参数可通过环境变量覆盖（见 `coned.py` 顶部）。

### 3.3 “在本车道前方(in-path)”判定（重要）

该版本不计算真实距离（米），只用图像 ROI + 面积阈值做启发式门控：

通用 ROI：
- `x`（框中心）必须落在 `[0.35w, 0.65w]`
- 框底 `y2 >= 0.55h`

面积阈值（避免远处小目标误触发）：
- 行人 `personInPathRaw`：`area >= CONE_PERSON_AREA_MIN_FRAC * (w*h)`（默认 `0.004`）  
- 两轮（自行车/摩托）`vehicleInPathRaw`：`area >= CONE_TWOWHEEL_AREA_MIN_FRAC * (w*h)`（默认 `0.006`）
- 四轮（小汽车/客车/货车）`vehicleInPathRaw`：`area >= CONE_VEHICLE_AREA_MIN_FRAC * (w*h)`（默认 `0.010`）
- 锥桶 `inPathRaw`：仅 ROI，无面积阈值

去抖（防闪烁，按 10Hz 发布频率计算）：
- `inPath/personInPath/vehicleInPath`：**连续命中 ≥ 2 次**才置 True；**连续未命中 ≥ 3 次**才置 False

### 3.4 接近程度指标（Metric：0~1）

`coned` 输出 `coneMetric/personMetric/vehicleMetric/obstacleMetric/hazMetric`：
- 对锥桶：主要由 `y2`（框底越靠近画面底部越“近”）
- 对人/车：由 `y2` + 面积综合（`0.6*y + 0.4*area`）
- `obstacleMetric = max(coneMetric, vehicleMetric)`
- `hazMetric = max(personMetric, vehicleMetric)`

此外有“保持+衰减”（减少抖动）：
- 变量：`CONE_METRIC_DECAY`，默认每次发布衰减 `0.12`（10Hz 下约 1.2/s）

### 3.5 目标车道前方占用距离（leftLaneHazDistM/rightLaneHazDistM）

`coned` 会额外输出相邻车道（左/右）最近“危险目标”的**粗略距离估计**（单位 m，`0.0` 表示无/不可用，作为 fallback）：

- 距离估算（针孔近似）：`dist_m ≈ focal_length_px * H / bbox_height_px`
  - 车辆假设高度：`H=1.5m`（可用 `CONE_LC_ASSUMED_VEHICLE_HEIGHT_M` 覆盖）
  - 行人假设高度：`H=1.7m`（可用 `CONE_LC_ASSUMED_PERSON_HEIGHT_M` 覆盖）
  - 锥桶假设高度：`H=0.7m`（可用 `CONE_LC_ASSUMED_CONE_HEIGHT_M` 覆盖；用于避免变道进入施工锥桶车道）
  - 锥桶占用的 score 门限：`CONE_LC_CONE_SCORE_MIN`（默认 `0.25`）
- 车道区域（图像近似，fallback）：按框中心 `x` 落点判断属于左/右车道，并要求 `y2 >= 0.20h`
  - 左侧默认：`x∈[0.05w, 0.40w]`（`CONE_LC_LEFT_LANE_X_*`）
  - 右侧默认：`x∈[0.60w, 0.95w]`（`CONE_LC_RIGHT_LANE_X_*`）
- 合并规则：同一侧取 `vehicle/person/cone` 距离中最小的非 0 值

`modeld` 还会在车道线置信度足够时做“更细”的版本（用于自动变道门控）：
- 数据来源：`payload.objs[]` + `payload.focalLengthPx` + `modelV2.laneLines[1]/laneLines[2]`
- 方法：先用车道线边界把目标归属到左/右相邻车道，再用 bbox 高度做 pinhole 粗距离估算，得到更精细的左右车道最小距离
- 使用：与 `coned` 的 fallback 粗估取更保守结果（min non-zero），用于收紧 `left_ok/right_ok`
- 可调：`DP_LINCOLN_AUTO_LC_LANE_LINE_PROB_MIN`、`DP_LINCOLN_AUTO_LC_LANE_MARGIN_M`

用途（严格按代码）：`modeld` 在**生成自动变道请求前**会用它做“目标车道前方占用”门控（避免目标车道前方有车/人还自动变道）：

- `target_lane_block_dist_m = clamp(vEgo * 2.0s, [25m, 90m])`
  - 可用环境变量覆盖：`DP_LINCOLN_AUTO_LC_TGAP_S / DP_LINCOLN_AUTO_LC_MIN_DIST_M / DP_LINCOLN_AUTO_LC_MAX_DIST_M`
- 若 `leftLaneHazDistM/rightLaneHazDistM` 在该距离内，对应侧 `left_ok/right_ok` 会被强制置 False
- 抗漏检“阻塞保持”（新增）：`DP_LINCOLN_AUTO_LC_BLOCK_HOLD_SEC`（默认 `0.8s`）
  - 作用：即使 YOLO 偶发漏检导致 `*HazDistM` 瞬间变 `0.0`，也会在短时间内继续认为该侧“被占用”，减少高速误触发变道

## 4. customReservedRawData0 消息格式（关键注意）

### 4.1 字段类型（导致过崩溃的根因）

`customReservedRawData0` 在 `cereal/log.capnp` 中定义为 `Data`：
- `cereal/log.capnp`：`customReservedRawData0 @124 :Data;`

因此发布时不能 `new_message("customReservedRawData0")`（那会走 `dat.init(service)`，**Data 必须带 size**）。

当前正确实现（coned）：
- `msg = messaging.new_message(None, valid=True)`
- `msg.customReservedRawData0 = payload`（直接赋 bytes，capnp 自动分配 size）
- `pm.send("customReservedRawData0", msg)`

### 4.2 Payload（JSON bytes）字段

编码/解码：`selfdrive/modeld/cone_detections.py`

顶层字段（简化）：
- `v`：版本（固定 1）
- `frameId/timestampSof/imgW/imgH`
- `focalLengthPx`：相机焦距（像素），用于 UI/`modeld` 侧做粗距离估算（可选）
- `inPath/inPathRaw`
- `personInPath/personInPathRaw`
- `vehicleInPath/vehicleInPathRaw`
- `hazInPath/hazInPathRaw`
- `coneMetric/personMetric/vehicleMetric/obstacleMetric/hazMetric`
- `leftLaneHazDistM/rightLaneHazDistM`：相邻车道前方占用距离估计（m，`0.0` 表示无/不可用）
- `cones[]`：锥桶框（x1,y1,x2,y2,s）
- `objs[]`：所有类别框（c,x1,y1,x2,y2,s）
- `objsR[]`：refine 后的框（优先用于 UI 绘制/追踪）

## 5. 纵向策略（减速/停车兜底）

代码：`selfdrive/controls/lib/longitudinal_planner.py`

触发条件：
- `dp_lincoln_auto_avoid == 1`
- `selfdriveState.enabled == True`
- `obstacle_present == True`（`inPath/personInPath/vehicleInPath` 任一为真）

行为：
1) **禁止继续加速靠近障碍物**：`accel_clip[1]` 被限制到 `<= 0`
2) **渐进式限速（更平顺）**：根据 `obstacleMetric` 把 `v_cruise` 上限从 `35mph → 12mph` 线性压低  
   - `OBSTACLE_APPROACH_SPEED_MPH = 35`
   - `OBSTACLE_SLOW_SPEED_MPH = 12`
   - `OBSTACLE_METRIC_START = 0.15`
   - `OBSTACLE_METRIC_FULL = 0.75`
3) **rate-limit 限速变化**（减少“点刹感”）
   - 收紧（降上限）最大步进：`OBSTACLE_V_CAP_DOWN_RATE = 8.0 m/s^2`
   - 释放（抬上限）最大步进：`OBSTACLE_V_CAP_UP_RATE = 2.0 m/s^2`
4) **行人更保守**：`personInPath == True` → 直接 `v_cap_target = 0`（停车，不绕行）
5) **3 秒兜底停车**：若障碍物持续 ≥ `3s` 且变道仍未开始（`laneChangeState` 仍为 `off/pre`），则 `v_cap_target = 0`
6) **无 BSM 时不绕行**：对锥桶/车辆类，若 `enableBsm==0` 则直接 `v_cap_target = 0`（避免在无法判断相邻车道安全时强行绕行）

## 6. 横向策略（自动绕行/回正）

### 6.1 触发条件（绕行请求入口）

代码：`selfdrive/modeld/modeld.py`

- `dp_lincoln_auto_avoid == 1`
- `carControl.latActive == True`
- `carParams.enableBsm == 1`
- `vEgo >= 30 km/h`
- 驾驶员未单边打灯（`leftBlinker != rightBlinker` 时禁用）
- 检测到障碍物：
  - 锥桶（收紧触发，防误触发变道）：
    - `cone_obstacle = payload.inPath && (payload.coneMetric >= DP_LINCOLN_AVOID_CONE_METRIC_MIN)`（默认 `0.25`）
  - 车辆（仅停/极慢车才触发绕行）：
    - `vehicle_in_path = payload.vehicleInPath`
    - 若 `leadOne` 存在：`v_lead < DP_LINCOLN_AVOID_STOPPED_LEAD_SPEED_MS`（默认 `3.0 m/s`）且 `vehicleMetric >= DP_LINCOLN_AVOID_VEHICLE_METRIC_MIN`（默认 `0.45`）
    - 若 `leadOne` 不存在：要求更近才触发 `vehicleMetric >= DP_LINCOLN_AVOID_VEHICLE_METRIC_MIN_NO_LEAD`（默认 `0.65`）
  - **仅锥桶/车辆触发绕行**（行人不触发绕行：更保守，触发停车兜底）
  - **绕行择侧（新增）**：当左右两侧都满足安全门控时，会根据障碍物框中心在画面左右的位置，优先绕到“障碍物的反方向”一侧（更像人类绕行）

### 6.2 AutoAvoidanceHelper 状态机（何时回正、为何不回正）

代码：`selfdrive/controls/lib/auto_avoidance.py`

关键参数：
- 最低速度：`AUTO_AVOID_MIN_SPEED = 30 km/h`
- 先减速等待：`SLOWDOWN_BEFORE_LC_SEC = 1.0s`
- 障碍物清除判定延迟：`OBSTACLE_CLEAR_DELAY_SEC = 2.0s`
- 变道完成后最短保持外侧：`RETURN_MIN_TIME_AFTER_OUT_SEC = 3.0s`（避免刚绕开就立刻回正）
- 两次绕行最小间隔：`AVOID_COOLDOWN_SEC = 8.0s`
- 相邻车道安全稳定：`CLEAR_LANE_STABLE_SEC = 0.6s`

安全门控（left_ok/right_ok）：
- `left_ok = enableBsm && !leftBlindspot && !left_edge_detected`
- `right_ok = enableBsm && !rightBlindspot && !right_edge_detected`
其中 `left_edge_detected/right_edge_detected` 来自 `RoadEdgeDetector`（`dragonpilot/selfdrive/controls/lib/road_edge_detector.py`，用于避免向路沿/护栏方向变道）。

目标车道前方占用门控（新增）：
- `modeld` 会根据 `leftLaneHazDistM/rightLaneHazDistM` 进一步收紧 `left_ok/right_ok`（见 §3.5）

侧方并行车辆保护（新增，视觉兜底）：
- 背景：BSM 主要覆盖后方盲区，无法可靠覆盖“并行/略靠前”的车辆；因此在目标检测可用时，`modeld` 会额外判断画面左右侧是否存在“近距离大目标”（车辆/行人/两轮等），若有则短时间内禁止向该侧发起**自动**变道请求（避免变道完成后与旁车平行又立刻触发下一次变道）。
- 代码：`selfdrive/modeld/modeld.py`
- 环境变量（默认值）：
  - `DP_LINCOLN_AUTO_LC_SIDE_BLOCK_HOLD_SEC=1.2`
  - `DP_LINCOLN_AUTO_LC_SIDE_Y2_MIN_FRAC=0.70`
  - `DP_LINCOLN_AUTO_LC_SIDE_AREA_MIN_FRAC=0.02`
  - `DP_LINCOLN_AUTO_LC_SIDE_X_GUARD_FRAC=0.06`

变道后冷却（新增）：
- 目的：避免“变道刚完成就又触发下一次自动变道”。
- 行为：当 `laneChangeState` 从 `laneChangeFinishing -> off` 时，`modeld` 会在短时间内屏蔽新的自动避让/自动超车变道请求。
- 代码：`selfdrive/modeld/modeld.py`
- 环境变量：`DP_LINCOLN_AUTO_LC_POST_FINISH_COOLDOWN_SEC=1.0`

绕行方向偏好（新增）：
- 当 `left_ok` 与 `right_ok` 都连续稳定（`0.6s`）时，`modeld` 会从 `payload.objsR/objs` 中挑选“最近的 in-path 障碍物”，用其 bbox 中心 `x` 偏移生成 `prefer_dir`，让避让优先绕到障碍物反方向一侧（但仍受 `left_ok/right_ok` 硬门控约束）。

为什么可能“不回原车道”（严格按状态机逻辑）：
- 障碍物一直没“清除”（`obstacle_in_path` 一直为真）→ 永远停留在 `waiting_return` 前
- 回正侧一直不满足 `0.6s` 连续安全稳定（BSM/路沿检测抖动）→ return_ok 不成立
- 驾驶员单边打灯且处于 `idle`（不允许启动避让）/车速过低/BSM 不可用 → 状态机 reset
- **自动打灯回灌导致的状态机打断**：Ford 平台注入 `Steering_Data_FD1.TurnLghtSwtch_D_Stat` 会让 `carState.leftBlinker/rightBlinker` 在变道结束瞬间仍为真，若 `DesireHelper` 因此走 `laneChangeFinishing -> preLaneChange`（而非直接到 `off`），`AutoAvoidanceHelper` 的“变道完成”判定（`finishing -> off`）就会漏判，从而不进入回正阶段

### 6.3 DesireHelper：无需驾驶员扭矩触发变道

代码：`selfdrive/controls/lib/desire_helper.py`

- 自动请求进入 `preLaneChange` 后，只要不盲点（含路沿检测）且持续 `3.0s`，就会强制 `torque_applied=True` 进入变道：
  - `AUTO_LANE_CHANGE_START_DELAY_SEC = 3.0s`

## 7. HUD 目标框（全类别目标框）

绘制代码：`selfdrive/ui/onroad/augmented_road_view.py` → `_draw_object_detections()`

追踪方式（重要）：
- `Cone_YOLO11n` 仅提供**单帧检测框**，不自带追踪
- `coned` 会额外生成 `objsR[]`：在每个检测框 ROI 内做一次轻量边缘/轮廓包围（Canny + contour boundingRect），用于让框更贴近目标外轮廓（可通过环境变量 `CONE_REFINE_EDGES=0` 关闭；其余阈值见 `selfdrive/modeld/coned.py` 顶部 `CONE_REFINE_*`）
- UI 侧使用轻量 **track-by-detection（SORT 风格）**追踪器，将检测框做 IoU 匹配 + 速度预测 + 平滑，减少抖动/闪烁：`selfdrive/ui/onroad/object_tracker.py`

工作条件（严格）：
- UI 订阅 `customReservedRawData0`
- payload 中 `objsR[]`（优先）或 `objs[]` 非空
- payload 中 `focalLengthPx`（可选）：用于 UI 端按 bbox 高度做**粗距离估算**（仅用于显示/调试）
- 最近一次更新距今不超过 `1s`（`DET_STALE_TIMEOUT_S = 1.0`）

绘制类别与颜色（当前实现）：
- **0..80 全类别都画框**（COCO-80 + cone）
- `person(0)`：蓝色
- `traffic cone(80)`：橙色
- 车辆类（`1..8`）：红色
- 交通控制/路侧设施（`9..12`）：黄色
- 动物（`14..23`）：紫色
- 其它类别：灰色

标签：
- 默认显示 `class_name score`
- 可选：`DP_DET_SHOW_TRACK_ID=1` 时追加 `#track_id`
- 可选：`DP_DET_SHOW_DISTANCE=1` 时追加 `xxm`（基于 `focalLengthPx` + 类别假设高度的粗距离估算）
- 框太小会自动隐藏文字（只画框），防止 HUD 太乱

若你“完全看不到任何框”，优先排查：
- `coned` 是否在跑（§2.1）
- 是否出现过 `capnp init() without a size` 类错误（§4.1）
- 你使用的是否是标准 UI（本实现绘制在 `selfdrive/ui/onroad/*`）

## 10. 已知限制（目前版本就这样）

- **没有完整的 meters 级障碍跟踪**：`inPath/*Metric` 仍是图像 ROI + 面积启发式（非 meters）；仅 `leftLaneHazDistM/rightLaneHazDistM` 是基于 bbox 高度的粗略距离估算，用于“目标车道前方占用”门控（§3.5）。
- **不会绕行行人**：行人触发停车兜底（更保守）。
- **相邻车道安全性仍较简化**：以 BSM + 路沿检测为主，并额外加入目标车道“前方占用距离”门控；不做对相邻车道车辆的完整预测/跟踪。
- **误检/漏检依赖模型与阈值**：自行车/电瓶车可能被识别为 person/bicycle/motorcycle 等，表现会不同（框/绕行/停车）。

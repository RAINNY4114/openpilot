## 林肯面板「显示性能信息」功能实现

> 目标：在其它分支中 1:1 复刻该功能。以下按照文件路径列出所有涉及的代码与逻辑，按顺序逐项移植即可。

---

### 1. 参数声明

- **文件**：`common/params_keys.h`
- **新增键**：
  ```cpp
  {"dp_lincoln_perf_info_enabled", {PERSISTENT, BOOL, "0"}},
  {"RoadName", {CLEAR_ON_MANAGER_START, STRING}},
  ```
  - `dp_lincoln_perf_info_enabled`：控制 HUD 是否绘制性能信息，默认关闭。
  - `RoadName`：（可选数据源）由 `mapd`（离线地图/OSM）写入的“当前道路名称”。HUD 底部优先显示它；若为空/无 mapd，则回退显示 GPS 经纬度。

---

### 2. Lincoln 设置面板开关

- **文件**：`selfdrive/ui/layouts/settings/lincoln.py`
- **位置**：HUD & Visualization 区块
  ```python
  toggle_item(
    title=lambda: tr("Show performance info"),
    description=lambda: tr("Display device performance information at the bottom: CPU temperature, memory usage, CPU usage, and FPS. Requires UI restart."),
    initial_state=self._params.get_bool("dp_lincoln_perf_info_enabled"),
    callback=lambda val: self._params.put_bool("dp_lincoln_perf_info_enabled", val),

  ```
  用户开关与 Params 绑定，无需额外逻辑。

### 3. UI 状态同步

- **文件**：`selfdrive/ui/ui_state.py`
- **初始化**：
  ```python
  self.dp_lincoln_perf_info_enabled = False
  ```
- **每帧更新**（`_update_settings_params`）：
  ```python
  self.dp_lincoln_perf_info_enabled = self.params.get_bool("dp_lincoln_perf_info_enabled")
  ```
  这样 onroad HUD 能即时响应面板开关。

### 4. Augmented Road View 渲染

**文件**：`selfdrive/ui/onroad/augmented_road_view.py`

#### 4.1 性能数据缓存

```python
self._perf_stats = {"cpu_temp": "N/A", "mem_usage": "N/A", "disk_free": "N/A"}
self._perf_thread = threading.Thread(target=self._perf_update_loop, daemon=True)
self._perf_thread.start()

self._params = Params()
self._params_memory = Params("/dev/shm/params")
self._road_loc_cache = "--"
self._road_loc_cache_t = 0.0
```

#### 4.2 后台采集 `_perf_update_loop`

```python
time.sleep(5)
while self._perf_running:
  stats = {
    "cpu_temp": self._read_cpu_temp(),
    "mem_usage": self._read_mem_usage(),
    "disk_free": self._read_disk_free(),
  }
  with self._perf_lock:
    self._perf_stats.update(stats)

  for _ in range(10):  # ~1s, supports fast stop
    if not self._perf_running:
      return
    time.sleep(0.1)
```
所有异常写入 `"N/A"`/`"ERR"`，避免阻塞渲染。

#### 4.4 `_draw_performance_info()`

```python
if not ui_state.dp_lincoln_perf_info_enabled:
  return

stats = self._get_perf_stats()
curvature_text, steering_text, torque_text = self._get_curvature_steer_torque()
direction_text = self._get_direction_label()
road_loc_text = self._get_road_location_text()
control_text = self._get_control_state_text()
mem_usage = stats.get("mem_usage", "N/A")
cpu_temp = stats.get("cpu_temp", "N/A")

items = [
  f"{tr('Curvature')} {curvature_text}/{steering_text}/{torque_text}",
  f"{tr('Direction')} {direction_text}",
  f"{tr('Road')} {road_loc_text}",
  f"{tr('Control')} {control_text}",
  # Ford/Lincoln: 纯 HUD 诊断信息（不依赖日志）
  # "弯道: 地图/视觉/无 G{0/1} L{0/1} P{N}"
  # - 弯道来源: 由 curveSpeedSource 映射 (0=无, 1=视觉限速, 2=地图融合限速)
  # - G: GPSQualityOK (1=GPS质量满足地图门控, 0=质量差会禁用地图限速以避免“错路急刹”)
  # - L: controlsState.longActive (1=openpilot纵向在控, 0=多为原车ACC在控)
  # - P: MapTargetVelocities 点数（0=mapd暂无输出/离线地图不可用/定位未命中）
  f"弯道: {src} G{gps_ok} L{long_active} P{map_points}",
  f"{tr('Memory')} {mem_usage}",
  f"{tr('CPU Temp')} {cpu_temp}",
]

# 根据文字宽度居中摆放，默认间隔 PERF_ITEM_GAP=140；若超出屏幕宽度则自动收缩间隔（最小 0px）
# 若仍超宽：会对 Road 字段做 `...` 省略，并将 bar_width 限制到可用宽度内，避免被 scissor 裁切导致“文字截断”
# 背景为半透明黑色圆角矩形（PERF_BG_COLOR），文本为白色
```

##### 方向获取（修复点）
- 优先使用 `gpsLocationExternal.bearingDeg`，若无效则用 `gpsLocationExternal` 的 `vN/vE` 估算方位；外部 GPS 不可用时回退到 `gpsLocation` 同样逻辑，再回退到 `livePose.velocityDevice`。仅在完全无效时显示 `---`。
- 对应逻辑：`AugmentedRoadView._get_direction_label()`。
- UI 订阅：`ui_state` 需订阅 `gpsLocationExternal`、`gpsLocation`、`livePose`，确保方向来源存在；如需复刻请同步 SubMaster 列表。

##### 道路/位置获取（新增）
- **优先**读取 Params：`RoadName`（来自离线地图 `mapd` 的道路匹配结果，通常是道路名称/编号）。
- **回退**读取 `gpsLocationExternal`/`gpsLocation` 的 `latitude/longitude`，格式化为 `lat,lon`（保留 5 位小数）。
- 逻辑入口：`AugmentedRoadView._get_road_location_text()`；内部带 0.5s 缓存；`RoadName` 不再固定按 22 字符截断（由渲染阶段按像素宽度做 `...` 省略）。
- 为避免 `mapd` 短暂输出空值导致“道路名/经纬度”来回跳变：若最近曾拿到过有效 `RoadName`，会按速度/停车状态保留（行驶 30s、低速 60s、停车 1h）。
- 为减少 GNSS 抖动/并行道路误匹配导致 `RoadName` 乱跳：当 `GPSQualityOK=0` 时会保持最近一次稳定的 `RoadName`；且 `RoadName` 变更需要稳定约 1s 才切换显示。
- 为避免 GPS 短暂无 fix 导致直接显示 `--`：在 `RoadName` 为空且取不到经纬度时，会按同样的保留时间回退显示“最近一次有效经纬度”。
- `mapd` 启动器写入 `LastGPSPosition` 并同时写入 `GPSQualityOK`（质量门控）；它订阅 `gpsLocationExternal` 与 `gpsLocation`，外部 GPS 不可用时会自动回退到内部 GPS（提高道路匹配命中率）。
- 为避免道路名出现 `?`（字体图集缺字）：当检测到当前字体缺少 `RoadName` 字形时，UI 会使用 `unifont.otf` 动态生成“仅包含当前道路名字符”的临时字体并缓存后绘制。
  - 同类现象：HUD 其它区域若出现 `?`（例如弯道控件上行显示 `地图?合`），本质也是“字体图集缺字”。原因是 `unifont.fnt`/`Inter-*.fnt` 的图集字符集合来自 `selfdrive/assets/fonts/process.py`（主要收集翻译文件与少量额外字符），硬编码/新出现的中文可能没被打进图集。
  - 解决思路：像 `RoadName` 一样做“动态 unifont 兜底”（检测缺字 → 从 `unifont.otf` 动态生成仅包含当前字符串字符的临时字体并缓存）；或把需要的文案字符加入翻译/额外字符集合后重新运行 `selfdrive/assets/fonts/process.py` 生成新的 `unifont.fnt/png` 并同步到设备。

### 6. 行为摘要

- 开关位于 Lincoln 面板 HUD 部分，写入 Params。
- `ui_state` 每帧读取开关，`augmented_road_view` 根据布尔值决定是否绘制/预留空间。
- 性能数据由后台线程每秒刷新，渲染线程只读缓存，CPU/GPU 负担极低。
- HUD 底部中央一次性显示 6 个字段；Ford/Lincoln 车型会额外插入 1 个 `弯道: ...` 诊断字段（含 `RoadName/GPS 经纬度`），背景为半透明黑色矩形，字体 32px；必要时会收缩字段间距，并对 Road 字段做 `...` 省略以确保不被裁切。

照上述步骤复制全部片段，即可在其它分支 1:1 还原“显示性能信息”功能。

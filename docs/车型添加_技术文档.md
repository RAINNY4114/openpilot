# 车型添加_技术文档（Ford 分支）

## 目标与前提
- 目标：新增航海家（Lincoln Nautilus）、锐界（Ford Edge）、新蒙迪欧（Ford Mondeo）三个车型，确保设备面板可选、手动/自动识别可用。
- 约束：不修改既有 `CAR.FORD_EXPLORER_MK6`（Explorer/Aviator）配置与指纹，但新车型共享 MK6 平台能力（同 DBC/控制逻辑）。
- 策略：三个 `CAR` 条目独立存在（保持独立指纹），但共享同一平台配置；当前阶段临时复用航海家 FW 列表用于 Edge/Mondeo，后续用真实指纹替换。

## 车型与平台策略（必须一致）
- CAR 键名：
  - `FORD_EDGE_MK2`
  - `LINCOLN_NAUTILUS_MK1`
  - `FORD_MONDEO_MK5`
- CarDocs：
  - `FordCarDocs("Ford Edge 2022", "Co-Pilot360 Assist+")`
  - `FordCarDocs("Lincoln Nautilus 2018-21", "Adaptive Cruise Control with Lane Centering")`
  - `FordCarDocs("Ford Mondeo 2022-24", "Co-Pilot360 Assist+")`
- CarSpecs：使用 MK6 近似值（与 `FORD_EXPLORER_MK6` 一致）
  - `CarSpecs(mass=2050, wheelbase=3.025, steerRatio=16.8)`
- Flags：
  - `FordFlags.ALT_STEER_ANGLE | FordFlags.ALT_GEAR`

## 设备面板/自动识别流程（现有逻辑）
- 车型列表来源：`system/manager/vehicle_model_collector.py`
  - 扫描 `opendbc_repo/opendbc/car/<brand>/values.py` 的 `CAR` 枚举
  - 写入 `dp_dev_model_list`
- 手动选择：设备面板选择车型写入 `dp_dev_model_selected`
  - `selfdrive/car/card.py` 将其作为 `dp_fingerprint` 传给 `get_car()`，强制使用指定车型
- 自动识别：主要依赖 `FW_VERSIONS`（Ford 以 FW 为主）
  - 由于三个车型当前 FW 列表相同，会出现多候选，自动识别无法唯一确定
  - 解决：阶段性使用手动选择；拿到真实 FW 后再恢复自动识别

## 必须修改的文件（代码完整清单）
### 1) `opendbc_repo/opendbc/car/ford/values.py`
- 新增 flags：
  - `FordFlags.ALT_STEER_ANGLE = 2`
  - `FordFlags.ALT_GEAR = 4`
- 新增三条 CAR（不修改 MK6）：
  - `FORD_EDGE_MK2`
  - `LINCOLN_NAUTILUS_MK1`
  - `FORD_MONDEO_MK5`
- 三车必须带 `flags=FordFlags.ALT_STEER_ANGLE | FordFlags.ALT_GEAR`

### 2) `opendbc_repo/opendbc/car/ford/fingerprints.py`
- 为每个新 CAR 添加独立 `FW_VERSIONS`
- 当前临时做法：将航海家 FW 列表复制到 Edge/Mondeo
  - 之后必须替换为真实指纹

### 3) `opendbc_repo/opendbc/car/ford/carstate.py`
- 关键变量与逻辑（必须与代码保持一致）：
  - `self.steering_msg = "SteeringPinion_Data_Alt" if ALT_STEER_ANGLE else "SteeringPinion_Data"`
  - `self.use_alt_gear = bool(ALT_GEAR)`
  - ALT_STEER_ANGLE 时：
    - 读取 `ParkAid_Data/ExtSteeringAngleReq2`
    - 使用 `EPASExtAngleStatReq == 0` 且 `ApaSys_D_Stat in (0, 1)`
    - 过滤无效值：`int((ExtSteeringAngleReq2 + 1000) * 10) not in (32766, 32767)`
    - 角度融合：
      - `StePinRelInit_An_Sns` 为初始角
      - 当有效时，`offset = ExtSteeringAngleReq2 - StePinRelInit_An_Sns`
      - `steeringAngleDeg = StePinRelInit_An_Sns + offset`
  - ALT_GEAR 时：
    - 使用 `TransGearData/GearLvrPos_D_Actl`

### 4) `opendbc_repo/opendbc/car/torque_data/override.toml`
- 新增 torque 参数条目（先用 Ford 默认值）：
  - `FORD_EDGE_MK2 = [nan, 1.5, nan]`
  - `LINCOLN_NAUTILUS_MK1 = [nan, 1.5, nan]`
  - `FORD_MONDEO_MK5 = [nan, 1.5, nan]`
- 说明：若缺失该条目，`get_torque_params()` 会抛 `NotImplementedError` 并阻断启动。

## 信号适配细节（必须一致）
### Steering（ALT_STEER_ANGLE）
- 消息与信号：
  - `SteeringPinion_Data_Alt/StePinRelInit_An_Sns`
  - `ParkAid_Data/ExtSteeringAngleReq2`
  - `ParkAid_Data/EPASExtAngleStatReq`
  - `ParkAid_Data/ApaSys_D_Stat`
- 说明：若 `ParkAid_Data` 实车在相机总线（cam）而非主总线（pt），需要把读取切到 `cp_cam` 并保证解析到该消息。

### Gear（ALT_GEAR）
- 消息与信号：`TransGearData/GearLvrPos_D_Actl`
- 说明：该信号在 `ford_lincoln_base_pt.dbc` 有 VAL 表，`parse_gear_shifter()` 会将字符串映射为枚举。

## FW 指纹临时策略（当前状态）
- 临时 FW（用于三车）：
  - EPS: `M2GC-14D003-AA`, `K2GC-14D003-AH`
  - ABS: `M2GC-2D053-CB`, `M2GC-2D053-EA`, `KG9C-2D053-MD`
  - RADAR: `JX7T-14D049-AD`
  - CAMERA: `KT4T-14F397-AF`, `KK7T-14F397-AD`
- 风险：三车 FW 完全相同会导致自动识别返回多候选，需要手动选择
- 解决：采集真实 FW 日志后，替换各自 `FW_VERSIONS`

## 验证步骤（上车/日志）
1) 设备面板手动选择车型（或写入 `dp_dev_model_selected`）
2) 启动后检查 `carlog` 中 fingerprint 是否为目标车型
3) 验证档位显示是否正确（P/R/N/D/S）
4) 验证转向角是否稳定、`vehicleSensorsInvalid` 不再常亮
5) 替换真实 FW 后，清空 `dp_dev_model_selected` 验证自动识别

## 常见问题/排查
- `vehicleSensorsInvalid` 持续为 True：检查 `ParkAid_Data` 是否存在、`EPASExtAngleStatReq`、`ApaSys_D_Stat` 是否符合条件
- 档位显示 Unknown：检查 `TransGearData` 是否在主总线出现
- 自动识别失败：检查 `FW_VERSIONS` 是否缺失或多候选，必要时先手动选择

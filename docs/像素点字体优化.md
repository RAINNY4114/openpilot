# 像素点字体/高分辨率 CJK 字体（方案 A：随远程更新下发字体图集）

## 1. 现象：C3 上部分中文显示成 “?”

在 comma C3（标准 UI / `pyray`）上，出现 `?` 通常不是翻译问题，而是**字体图集里没有这个字形**。

openpilot 的标准 UI 并不是运行时直接用 `.ttf/.otf` 渲染，而是加载 **BMFont 图集**：

- 纹理：`selfdrive/assets/fonts/*.png`
- 描述：`selfdrive/assets/fonts/*.fnt`
- 关键 fallback 字体：`unifont.fnt`（中文/日文/韩文会走 fallback）

相关代码位置（用于理解链路）：

- `system/ui/lib/multilang.py`：`requires_unifont()`（哪些语言必须用 unifont）
- `system/ui/lib/application.py`：`FontWeight.UNIFONT` + `font_fallback()`（实际加载 unifont.fnt）

## 2. 为什么“本地跑命令能好，推送远程更新却不生效”

你本地执行 `selfdrive/assets/fonts/process.py` 后变正常，是因为它**重新生成**了 `unifont.png/unifont.fnt`，把 `.po` 翻译文件里出现的字符打进图集。

但如果设备端只是“拉取远程更新”（git 更新），而字体产物没有随更新下发，设备仍会继续使用旧图集 → 还是 `?`。

本仓库之前的关键问题是：字体产物默认被忽略，无法随远程更新下发：

- `selfdrive/assets/.gitignore` 原来包含 `fonts/*.png`、`fonts/*.fnt`

## 3. 方案 A（推荐）：把生成产物纳入更新包（设备端无需任何命令）

目标：**开发机/CI 生成 → 提交到仓库 → 设备远程更新直接获得新字体图集**。

已落地的改动点（给其他 AI 复刻/对照用）：

1) 取消忽略字体图集产物（让它们可以被 git 更新到设备）

- 修改文件：`selfdrive/assets/.gitignore`
- 动作：移除 `fonts/*.png`、`fonts/*.fnt` 两行

2) 让 SCons 在翻译变更时自动重建字体（避免“翻译加了字，但字库没更新”）

- 修改文件：`selfdrive/ui/SConscript`
- 动作：把 `selfdrive/ui/translations/languages.json` 和 `selfdrive/ui/translations/app_*.po` 加入字体生成的依赖源

3) 把生成后的字体产物提交到仓库（这是方案 A 的核心）

- 至少需要：`selfdrive/assets/fonts/unifont.fnt`、`selfdrive/assets/fonts/unifont.png`
- 通常也会包含 Inter 等字体对应的 `.fnt/.png`（取决于你是否把它们也纳入版本控制）

## 4. 生成与提交流程（开发机/CI 上做一次即可）

### 4.1 选择字库尺寸（影响清晰度/文件大小）

- `UNIFONT_SIZE=64`：默认推荐（清晰，文件不至于过大）
- `UNIFONT_SIZE=72/80`：更清晰，但 `unifont.png` 更大
- `UNIFONT_SIZE=16`：点阵像素风（更“像像素点字体”，但中文细节会明显变糊）

### 4.2 生成字体图集

在仓库内执行（Windows PowerShell 示例）：

```powershell
cd E:\openpilot\selfdrive\assets\fonts
$env:UNIFONT_SIZE="64"
python process.py
```

说明：

- `process.py` 会读取 `selfdrive/ui/translations/languages.json` 与 `app_*.po`，自动收集字符集合并生成图集
- 会覆盖写入：`unifont.fnt/unifont.png` 以及其它字体对应的 `.fnt/.png`

### 4.3 提交到仓库（让设备远程更新能拿到）

```bash
git add selfdrive/assets/fonts/*.png selfdrive/assets/fonts/*.fnt
git add selfdrive/assets/.gitignore selfdrive/ui/SConscript
git commit -m "Ship regenerated font atlases for CJK"
git push
```

设备端只需要正常更新 + 重启 UI（或重启整机）即可，不需要手动 `python process.py` / `rsync`。

## 5. 验证与排障

1) 快速确认生成参数是否生效：

- 打开 `selfdrive/assets/fonts/unifont.fnt`，第一行应类似：`size=-64`（对应 `UNIFONT_SIZE=64`）

2) 更新后仍有 `?`：

- 先确认该字符是否出现在 `.po` 文件里（`process.py` 的字符集合来自 `.po` 内容）
- 若是“代码里硬编码的中文字符串”，不在 `.po` 里：需要把字符加入 `selfdrive/assets/fonts/process.py` 的 `EXTRA_CHARS`，或把该字符串纳入翻译体系

3) 语言没走 unifont：

- 只有 `ar/th/zh-CHT/zh-CHS/ko/ja` 会触发 `requires_unifont()`，其它语言不会加载 unifont 作为 fallback

## 6. 为什么“道路/逆地理编码”更容易出现 `?`

HUD 底部“道路信息”（例如 `RoadName`）通常来自 **OSM 匹配/逆地理编码**，它是**动态字符串**：

- 它不会出现在 `app_*.po` 翻译文件里（`process.py` 默认也不会自动把它的字符打进字体图集）
- 真实道路名经常包含“地名用字/生僻字/符号”（例如 `—/～/·/（/）` 等），很容易超出当前 `unifont.fnt` 的字符覆盖范围
- 你本地可能看不到：因为 PC 上没有相同的 GPS/地图匹配结果，UI 常常显示 `--` 或经纬度，所以触发不到缺字场景

判断思路：

- 若设备端 `RoadName` 原始值是正常中文，但 UI 显示成 `?`：几乎可以确定是**字体图集缺字**（不是地图解析坏了）
- 若 `RoadName` 原始值里就已经是 `?`：才考虑**上游写入/编码**链路（mapd/解析器）把字符损坏了

解决方向（仍然遵循“设备端不跑命令，只靠远程更新”）：

- **动态兜底字体（覆盖最好）**：对 `RoadName` 这种“运行时动态字符串”，在 UI 渲染时用 `unifont.otf + load_font_ex()` **按需生成仅包含当前道路名字符的临时字体**（并做 LRU 缓存），避免把大量汉字打进固定图集导致纹理过大；推荐用于“道路名/地名”这类不可控字符集场景。
- **扩充字符集**：在 `selfdrive/assets/fonts/process.py` 中把道路可能用到的字符纳入图集生成（推荐“常用汉字 + 常见符号”策略），然后重新生成并提交 `selfdrive/assets/fonts/unifont.{fnt,png}`。
- **兜底策略**：若检测到道路名包含未覆盖字符，则回退显示经纬度或 `--`，避免 UI 出现 `?`（信息不完整但视觉更干净）。

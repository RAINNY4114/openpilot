# Cone_YOLO11n (YOLO detect model)

This ONNX model is consumed by `selfdrive/modeld/coned.py`.

In this repo we currently use it for:
- **auto-avoid trigger**: `traffic cone (80)` (`inPath`)
- **HUD boxes / hazard chime**: a small subset of classes (see `selfdrive/modeld/coned.py`)

Model output is YOLO-style `float32[1,85,2100]` (4 box coords + 1 objectness + 80 class scores).
The embedded `names` metadata declares **81 labels (0..80)**: COCO-80 plus `traffic cone (80)`.

## Labels

Relevant driving-related labels (from ONNX metadata `names`):
- `0 person`
- `1 bicycle`
- `2 car`
- `3 motorcycle`
- `5 bus`
- `7 truck`
- `9 traffic light`
- `11 stop sign`
- `80 traffic cone`

Note: `coned.py` currently only parses/uses the subset above (plus `traffic cone`); other labels exist but are ignored.

## Regenerating `Cone_YOLO11n.onnx` (developer machine)

1. Download weights:
   - `https://github.com/Hamadeen99/Cone-YOLO/raw/main/Cone_YOLO11n.pt`
2. Export to ONNX:
   ```bash
   python -c "from ultralytics import YOLO; YOLO('Cone_YOLO11n.pt').export(format='onnx', imgsz=320, opset=17, dynamic=False)"
   ```
3. Copy the resulting `Cone_YOLO11n.onnx` into this folder.

Note: `ultralytics` is only used for export on a dev machine; runtime inference on the device uses `tinygrad` via the `*_tinygrad.pkl` artifact generated by the build.
